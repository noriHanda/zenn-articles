## あのメール、見覚えありませんか

Googleアカウントに新しいデバイスからログインすると、こんなメールが届きます。

> 新しいデバイスからのログイン
> お使いのGoogleアカウントが**千代田区, 日本**付近で新しいデバイスからのログインに使用されました。

自分は千代田区に住んでいないし、その日千代田区に行った覚えもない。なのに「千代田区」と表示される。Google以外にも、Apple、Microsoft、GitHub、Slackなど、多くのサービスで似たような通知を目にした方は多いのではないでしょうか。

この記事では、なぜログイン通知がいつも「千代田区」を指すのか、その技術的な仕組みを解説します。

## 結論

**IPアドレスから位置情報を推定する仕組み（IPジオロケーション）が、日本のISPのIPアドレスブロックを千代田区付近の座標に紐づけているから。**

もう少し正確に言うと、以下の要因が重なっています。

1. ISPがJPNICに登録するIPアドレスブロックの情報に、本社所在地（東京都心）が記載されている
2. ジオロケーションデータベースが、個別の位置を特定できない場合にその登録情報をフォールバック値として使う
3. 千代田区は日本の多くの主要ISP・通信事業者の本社や登記上の拠点が集中する場所である

順を追って見ていきましょう。

## IPジオロケーションの仕組み

### IPアドレスから場所を推定する

Webサービスがログイン通知に位置情報を含めるとき、GPSを使っているわけではありません。使っているのは**IPジオロケーション**という技術です。

ログイン時にサーバーが取得できるのは、クライアントのIPアドレスだけです。このIPアドレスから地理的な位置を推定するために、**ジオロケーションデータベース**が使われます。代表的なものに[MaxMind社のGeoIP2](https://www.maxmind.com/en/geoip-databases)やIP2Location、DB-IPなどがあります。

### データベースはどうやって位置を決めているのか

ジオロケーションデータベースは、以下のような情報源を組み合わせてIPアドレスと位置のマッピングを構築しています。

| 情報源 | 精度 | 説明 |
|--------|------|------|
| WHOIS / RIR登録情報 | 低〜中 | IPアドレスブロックの割り当て先組織の登録住所 |
| BGPルーティング情報 | 低 | IPアドレスがどのネットワークから広告されているか |
| Wi-Fiアクセスポイント | 高 | モバイル端末から収集したWi-Fi位置情報との紐づけ |
| ユーザー申告データ | 中 | Webサイトの登録情報や許諾済みの位置情報 |
| トレーサウト・遅延測定 | 中 | ネットワーク遅延からの距離推定 |

精度の高い情報源ほどカバー範囲が限定的で、すべてのIPアドレスに対して正確な位置がわかるわけではありません。

### フォールバックの階層構造

位置を特定できない場合、データベースは段階的にフォールバックします。

```
特定のビル・施設の住所  （精度: 高）
    ↓ 特定できない場合
市区町村レベル          （精度: 中）
    ↓ 特定できない場合
ISP/組織の登録住所       （精度: 低）← ★ここが千代田区になりがち
    ↓ 特定できない場合
国の代表座標            （精度: 最低）
```

多くの場合、日本のISPが保有するIPアドレスブロックは「ISP/組織の登録住所」までしか絞り込めず、ここで千代田区付近の座標が返されることになります。

## なぜ「千代田区」なのか

### JPNICとIPアドレスの管理構造

日本のIPアドレスは、以下の階層で管理されています。

```
IANA（全世界のIPアドレス管理）
  └─ APNIC（アジア太平洋地域）
       └─ JPNIC（日本）
            └─ 各ISP・企業
```

[JPNIC（一般社団法人日本ネットワークインフォメーションセンター）](https://www.nic.ad.jp/)は、日本国内のIPアドレス割り当てを管理する組織です。ISPがIPアドレスブロックの割り当てを受ける際、JPNIC（またはAPNIC）のWHOISデータベースに組織名と住所を登録します。

### 主要ISPの本社が東京都心に集中している

ここが核心です。日本の主要なISP・通信事業者の本社所在地を見てみましょう。

| 事業者 | 本社所在地 |
|--------|-----------|
| NTTコミュニケーションズ | 千代田区大手町 |
| NTTドコモ | 千代田区永田町 |
| KDDI | 千代田区飯田橋（一部は新宿区） |
| ソフトバンク | 港区海岸（竹芝） |
| IIJ | 千代田区富士見 |
| NTT東日本 | 新宿区西新宿 |

千代田区を本社・登記拠点としている事業者が多いことがわかります。これらの事業者がWHOISに登録する住所は本社所在地であり、その情報がジオロケーションデータベースにフォールバック値として取り込まれます。

さらに、**JPNIC自体の所在地も千代田区（神田駿河台）**です。IPアドレスブロックの上位の登録情報にJPNICの住所が記載されるケースもあり、これも千代田区にマッピングされる一因です。

### 実際のWHOISデータを見てみる

試しに、NTTコミュニケーションズが保有するIPアドレスブロックのWHOIS情報を確認すると、住所欄に千代田区の住所が記載されていることがわかります。

```
% whois 210.145.0.0

[Whois Result]
Network Information:
a. [Network Number]     210.145.0.0/16
b. [Network Name]       OCN
...
g. [Organization]       NTT Communications Corporation
m. [Administrative Contact] JP00000000
n. [Technical Contact]  JP00000000
...
[Address]               Otemachi Place, 2-3-1 Otemachi, Chiyoda-ku, Tokyo
```

ジオロケーションデータベースは、このIPブロックに属するアドレスについて、より詳細な情報がない限り、この登録住所に基づいた座標を返します。結果として「千代田区」になるわけです。

### 千代田区だけではない場合もある

ソフトバンクのIPアドレスでは「港区」と表示されることがあります。また、地方のケーブルテレビ局のIPアドレスでは、その会社の所在地（地方の市町村）が表示されることもあります。

ただし、NTT系列（フレッツ光、OCN、ドコモ）やKDDI（au光、UQ mobile）のシェアが大きいため、日本のインターネットユーザーの多くが「千代田区」を見ることになります。

## OAuthのログイン通知で使われるまでの流れ

実際にGoogleアカウントで新しいデバイスからログインしたとき、内部的にはこういう流れが起きています。

```
1. ユーザーがログインリクエストを送信
2. Googleのサーバーが接続元IPアドレスを取得
3. IPジオロケーションデータベースに問い合わせ
4. データベースが「千代田区付近（35.69, 139.69）」を返す
5. セキュリティシステムがリスク評価
   - 普段と違う場所？ → アラート
   - 新しいデバイス？ → アラート
6. メール通知に「千代田区, 日本」と記載して送信
```

GoogleやAppleは自社でジオロケーションデータベースを保有・運用しています。MaxMindなどの商用データベースに加え、AndroidやiOSデバイスから収集したWi-Fi・GPS情報も活用して精度を高めていますが、それでもISPのIPアドレスブロック単位でしか特定できない場合はフォールバック値が使われます。

## 「千代田区」は正しいのか、心配すべきか

### 心配しなくてよいケース

- 自分が日本国内からログインした覚えがある
- 表示されているデバイスに心当たりがある
- 「千代田区」以外の情報（デバイス名、ブラウザ名など）が正しい

IPジオロケーションは「だいたいこのあたり」を示しているだけで、正確な位置を示しているわけではありません。千代田区に住んでいなくても千代田区と表示されるのは正常です。

### 注意すべきケース

- 自分がログインした覚えがまったくない
- 表示されているデバイスに心当たりがない
- 「千代田区」ではなく海外の都市名が表示されている

この場合は不正アクセスの可能性があるため、すぐにパスワードを変更し、二要素認証を設定しましょう。

## 同様の現象は海外でもある

この現象は日本に限った話ではありません。

- **アメリカ**：カンザス州の農場の座標（39.8283°N, 98.5795°W）がアメリカの地理的中心点として使われ、全米から苦情が殺到した[有名な事例](https://arstechnica.com/tech-policy/2016/08/kansas-couple-sues-ip-mapping-firm-for-turning-their-life-into-a-digital-hell/)があります
- **イギリス**：ロンドン中心部が表示されがち
- **韓国**：ソウル特別市が表示されがち

各国のISPの本社や、IPアドレス管理組織の所在地が首都圏に集中しているため、同じ構造の問題が起きています。

## まとめ

| 疑問 | 答え |
|------|------|
| なぜ千代田区？ | 日本の主要ISPの本社・JPNICの所在地が千代田区に集中しているから |
| 位置情報の仕組みは？ | IPジオロケーション（IPアドレスから位置を推定するデータベース） |
| GPSを使っている？ | 使っていない。サーバーサイドではIPアドレスしか見えない |
| 心配すべき？ | ログインに心当たりがあれば問題なし。覚えがなければ要対応 |

「千代田区からログインしました」は、多くの場合「日本のどこかからログインしました」程度の意味しかありません。IPジオロケーションの限界を知っていれば、無駄に不安にならずに済みます。逆に、本当に不審なログインを見分ける目を養うためにも、この仕組みを知っておくことは有益です。
